**新DMの配置・入口の提案 v0.1**

> 2026-09-08の実装開始指示により、この文書の方針を採用しました。本文中の「推奨」「未確定」「未実装」は提案時点の記録です。現時点の実装範囲・検証済み項目・公開前に残る確認は [README](README.md) を正とします。

2026年9月8日。配置案としての提案であり、画面・コードは変更していない。[機能要件 v2.1](予約前DM_改善要件書.md)を前提とする。サービス全体の役割切替やナビゲーションの再設計は別タスク。

**推奨する配置**

既存のヘッダーにある「メッセージ」を連絡機能の入口として使う。開いた先は、その役割専用のメッセージ画面とし、「DM」「予約の連絡」の2タブに分ける。画面上部に利用者としての操作か、タチキャストとしての操作かを常時表示する。入口が共通でも、会話・履歴・未読・通知・権限を統合する意味ではない。

| 操作中の役割 | 画面タイトル | DMタブ | 予約の連絡タブ |
|---|---|---|---|
| 利用者 | 利用者としてのメッセージ | 自分が利用者として相談したキャストとのDM | 自分が利用者として行った予約ごとのチャット |
| タチキャスト | タチキャストとしてのメッセージ | 自分のキャストプロフィールに届いた利用者からのDM | 自分がキャストとして受けた予約ごとのチャット |

タブ名は両側とも「DM」「予約の連絡」で統一する。「予約前」だけをタブ名にすると予約後に残るDMの所在が曖昧になるため、DMタブの説明に「予約前の質問などをやり取りできます」と添える。DM一覧は相手単位、予約の連絡は予約日時・予約番号が分かる予約単位とする。

**利用者側の開始と再訪**

新しく相談する入口は、キャストの公開プロフィールに置く「予約前に質問する」。既存の予約・空き時間確認エリアに並べ、予約の主ボタンに対して補助ボタンとして表示する。スマートフォンでも同じ予約操作エリアから到達できる位置に置く。DMのために空き時間・メニュー・住所を先に選ばせない。DM受付ONなら、オフライン・空き枠なしでも相談できる。

押した後は「利用者として相談します」と利用者用の表示名・アイコン、対象キャストを示す。キャストモードから来た場合も利用者用プロフィールで送ることを示し、明示的な操作で利用者側へ進む。すでに同じ向きのDMがあれば開き、未作成なら入力画面だけを開く。初回送信まではDMも通知も作成しない。ログインが必要な場合も対象を保持して戻る。

再訪は「メッセージ → DM」から行う。プロフィールから既存DMを開くボタンは「DMを開く」に変えられる。受付OFFは新規開始だけを止めるため、既存DMへの入口は残す。自己プロフィールには送信ボタンを出さない。ブロック時は理由や別役割を示さず、相談・予約とも利用不可の状態を示す。

DM画面には利用者側だけ「予約する」を置き、当該キャストの既存予約手続きへ進める。予約後の当日の連絡は、予約詳細の「予約の連絡」から既存チャットへ進む。DMを予約チャットへ変換しない。

**タチキャスト側の受信と設定**

主な受信入口は「メッセージ → DM」。利用者から来た相談一覧として表示し、初期版では知らない利用者を検索して営業DMを開始する入口を作らない。会話画面には「タチキャストとして返信」と自分のキャスト公開名・アイコンを表示する。

DMタブの上部に「新しいDMの受付：ON／OFF」を置く。初期ON、OFFに変更しても既存の会話は続く旨を短く説明する。予約のオンライン受付とは別の設定であることを明記する。設定はDMタブを正規の配置場所とし、将来キャスト設定からリンクする場合も同じ設定へつなぐ。

**既存メッセージ入口の動作**

| 入口 | 開く先 |
|---|---|
| 利用者画面のヘッダー「メッセージ」 | 利用者専用のメッセージ画面 |
| キャスト画面のヘッダー「メッセージ」 | キャスト専用のメッセージ画面 |
| 公開ページのヘッダー「メッセージ」 | 現在明示的に選択している役割の画面。未選択で兼任なら、役割を選んでから開く |
| キャストプロフィールの「予約前に質問する」 | その相手への利用者役割のDM |
| DMの通知 | 受信した役割の該当DM。役割が違えば本文を出す前に切替を案内 |
| 予約詳細・既存予約通知 | その予約の既存チャット。DMタブへ寄り道させない |

ヘッダーの未読は現在の役割のDMと予約チャットの未読メッセージ数だけを合算し、各タブに内訳を表示する。逆役割の未読を足さない。役割未選択なら合計数・本文は取得表示しない。別役割の受信内容を見せるための追加バナーは今回の範囲に含めない。

初めて通常のメッセージ入口を開いた時は、既存利用者が迷わないよう「予約の連絡」を初期タブにする。以降は本人・役割ごとに最後に開いたタブを記憶する。プロフィールや通知からの直接遷移はその指定先を優先し、未読の発生だけで勝手にタブを切り替えない。

**今回の追加に含める最小変更**

1. 既存メッセージ入口を、役割が分かる宛先へ接続する。
2. メッセージ画面にDM／予約の連絡タブを追加し、一覧・未読の取得をその役割に限定する。
3. 公開キャストプロフィールに質問ボタンを追加する。
4. DM画面・役割表示・DM受付設定・通知からの直接遷移を追加する。
5. 予約詳細のリンク文言を「予約の連絡」に揃え、既存予約別チャットへの遷移を維持する。

メッセージ画面内の役割分離は新DMを誤った人格で使わないための追加範囲とする。一覧の取得と未読集計を直さずにタブだけ足すと混在が残るため、この部分は実装時の依存条件。ダッシュボード全体、予約・売上・プロフィール等のメニュー再編、サービス全体のロール切替、出張リクエスト整理は別タスクとする。既存課題の修正タスクが先行する場合は、その成果を利用し重複実装しない。

**既存コードとの対応**

| 確認した既存実装 | 配置案への影響 |
|---|---|
| PublicHeaderBar・DashboardLayoutがBookingMessagesLinkを配置 | 今あるヘッダーの入口を利用できる |
| /user/messages・/therapist/messagesが同じBookingMessagesPageを表示 | それぞれに操作役割を明示的に渡し、同じ部品でも取得対象を分ける |
| BookingMessagesPageがgetActiveRoles(account)から全保有ロールを取得する | 見た目の役割だけでなく、API取得範囲を限定する必要がある |
| BookingMessagesLinkの未読も全保有ロールを集計する | 現在の役割の未読だけに変更する必要がある |
| /messagesがactiveRole、未選択なら最初の保有ロールに遷移する | 兼任かつ役割未選択時に最初の役割を勝手に選ばない |
| RoleRouteがURLに従いselectRoleを自動実行する | 新DM・通知は本文取得前の役割確認を経由させる。全サイトの切替再設計には広げない |

実装用の経路案は、一覧が /user/messages と /therapist/messages、タブが ?tab=dm と ?tab=bookings、新DMの会話が /user/direct-messages/:id と /therapist/direct-messages/:id。既存の /{role}/bookings/:id/messages は予約チャットのまま。経路名は仮案。URLと所有するプロフィールの両方で認可し、直アクセスや複数タブでも別役割の内容を混在させない。

**この配置案の確認条件**

- 兼任アカウントの両役割で、ヘッダーの未読数と2つのタブの内容が一致する。
- 同じ相手との逆役割DMと複数予約を用意しても、会話が統合されない。
- プロフィールから質問を開始する時に、送信する利用者名を本人が確認できる。
- 未読DMの通知から、別役割の文章を経由せず正しいDMへ戻れる。
- 予約詳細や旧通知からは、従来の予約別チャットへ直接戻れる。
- 受付OFFでも既存DMへ戻れ、既存の予約可否は変わらない。

今回の確認はローカル実装の読み取りであり、本番画面での表示・クリック検証は行っていない。
