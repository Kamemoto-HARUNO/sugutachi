# ローカルで依頼送信後を確認する

DM確認環境（http://127.0.0.1:8018）では、Stripeへ接続せずに有料予約の与信・売上確定・取消・返金成功を再現できる。

## 操作

1. 利用者でログインし、ローカル確認キャストのプロフィールから通常どおり依頼へ進む。
2. 見積もり画面の「模擬決済で依頼を送る」を押す。カード入力や実際の請求は発生しない。
3. 別ブラウザまたは別ブラウザプロファイルで確認用キャストにログインし、依頼を承諾する。同じブラウザの別タブはログイン状態を共有するため避ける。
4. 利用者側の予約詳細・予約メッセージで、その後の流れを確認する。予約前DMとは別の会話になる。
5. 「今すぐ」の依頼には通常どおり10分の承諾期限がある。移動開始後、利用者に表示される到着確認コードをキャストが入力し、開始・完了・利用者の完了確認へ進む。

## 有効化条件

ローカルの `.env` に `LOCAL_PAYMENT_SIMULATION=true` を設定する（既定false）。以下の条件をすべて満たす場合のみ、サーバー側で有効になる。

- APP_ENVがlocal。
- APP_URLのホストがlocalhostまたはループバックアドレス。
- Stripe秘密キーが未設定。
- 実際に接続するDBがSQLiteで、ファイルがこの作業ツリーの `database/dm-preview.sqlite` と一致する。

本番・staging・通常のMySQLでは、フラグがtrueでも有効にならない。画面の値だけを変えても模擬決済は有効にならない。既存のStripe決済IDを模擬決済で処理することも拒否する。本人確認、予約条件、ブロック、承諾期限などは通常の処理を使う。ブロックの精算確認中は模擬売上確定も拒否する。

模擬決済IDは `pi_local_`、返金IDは `re_local_` で始まる。ローカルの予約・残高・通知記録は作られるが、Stripeの決済や送金は行わない。外部通知と定期処理は既存のローカル起動設定に従い無効のままとする。

実際のStripe接続、3Dセキュア、カードエラー、Webhook、送金の検証には使用できない。本番反映前には別途Stripeテスト接続で検証する。

## 検証（2026-09-09）

- API: 有料見積もり→予約→模擬与信→承諾待ち→承諾→予約メッセージ→移動・到着・開始→完了→売上確定、部分返金、与信取消を確認。
- 保護: local以外、フラグ無効、Stripe秘密キーあり、外部URL、MySQL、別SQLiteファイルは無効。既存Stripe IDは拒否。ブロック精算確認中の売上確定は拒否。
