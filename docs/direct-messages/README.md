# 役割別の予約前DM：実装・検証・公開手順

2026-09-08。既存の予約チャットを維持し、利用者プロフィールとタチキャストプロフィールの組合せごとに独立したDMを追加する。逆の役割での会話は別スレッドになる。この文書が実装時点の状態を示す。その他の同梱文書は、ユーザーが採用した要件と改修前調査の記録。

## 画面と利用動線

- 既存ヘッダーの「メッセージ」から、現在の役割専用の「DM」「予約の連絡」を開く。初回は予約の連絡、以後は本人・役割ごとの最後のタブを記憶する。
- 公開キャストプロフィールの「予約前に質問する」から利用者として相談する。初回送信までは会話・通知を作成しない。既存の会話があれば「DMを開く」と表示する。
- タチキャストのDMタブで新規受付をONにする。初期OFF。受付OFFへの変更後も既存の会話は続く。予約受付のオンライン状態とは独立する。
- 会話には送信する役割・自分の表示名を明示する。違う役割のリンクを開く場合は、本文取得前に切替を案内する。下書きは本人・役割・会話ごとのメモリ内に保持し、ログアウトで消去する。
- テキスト1,000文字、または画像1点10MiBまで。JPEG・PNG・WebPを再符号化し、EXIFと元名を除去して非公開領域へ暗号化保存する。画像は毎回参加役割を認可する。
- 利用者側の「予約する」は相手の既存予約導線へ戻る。予約成立後の連絡は予約ID別の既存チャットを使う。
- 通報、ミュート、アーカイブ、DM送信停止、役割単位のブロック、通知設定を追加する。管理画面には「DM・精算確認」と通報証拠の監査付き閲覧を追加する。

サイト全体のロール切替・ナビゲーション再編は別の改修範囲。

## ブロックと決済

ブロックは利用者→タチキャストの向きを保持して、DM・予約チャットの送信・見積・新規予約・決済認証・出張依頼・承諾等に共通適用する。既存のAccountBlockは従来の範囲を保持し、新方式の解除で弱めない。相手向けの表示や応答には共通アカウントID・逆役割の名前を出さない。

キャストがブロックした時点の予約を、アカウント行と予約行のロック内で再確認する。

| 予約状態 | 動作 |
| --- | --- |
| 決済認証中・申込中・承諾済み・移動中・到着済み | 全該当予約を取消。利用者負担0円。利用枠は解除、請求済みの未返金額は全額返金 |
| 開始後・キャスト完了報告済み・中断・未着確認中 | 接触停止、精算を運営確認へ。自動売上確定を保留 |
| 完了済み | 過去予約を取り消さない |
| 利用者によるブロック | 接触停止。無料キャンセル・自動返金は発生しない |

取消と外部返金の完了を分ける。外部処理が失敗してもブロック・取消は維持し、永続的な処理記録から再試行する。返金IDを先に保存し、同じ冪等キーを使用する。応答不明が長時間続く場合はStripe側のメタデータと照合し、判定できなければ運営確認とする。解除しても予約・抑止済み通知は復活しない。

接続先への送金がある返金では、対象の送金・手数料も戻す指定を行う。[Stripe公式のdestination charge返金仕様](https://docs.stripe.com/connect/destination-charges)に基づく。実際の接続先・返金・Webhookでの試験は公開前の確認項目。

## 保存・通知・計測

- DM本文・画像は各送信から365日。退会者の送信分は通常期限と退会90日の早い方。退会者の名前・写真・画像取得を停止し、本文の期限とは分けて扱う。
- 通報の必要原文・画像は別の非公開コピー。90日ごとに見直し、解決後原則1年。保全延長は理由・担当管理者・次回見直しを記録する。
- 本人の画像削除はブロック後も可能。削除履歴を残し、復元時に本文や画像が再公開されないよう適用する。孤立した暗号化ファイルも定期削除する。
- DMの外部通知は「新しいメッセージがあります」のみ。相手名・本文・画像を含めない。役割ごとの通知設定、既読・ミュート・ブロックを配送直前に確認する。プッシュは1分、未読メールは5分待ち・30分間隔。失敗時は1/5/30分後に再試行、4回で失敗扱い。
- `direct-messages:metrics` で初回相談に対する24時間返信、同じ向きの7日予約・30日完了を集計する。観測期間未了を分母に含めず、試験アカウント・管理者アカウント・通常群、無料/有料を分ける。DMを経由した因果効果を証明する値ではなく、相談後の同一役割ペアの到達指標。相手向けAPIには公開しない。

## 一時停止と復元

`DIRECT_MESSAGES_SENDING_ENABLED=false`で送信だけを停止できる。`DIRECT_MESSAGES_ENABLED=false`でも履歴の閲覧・既存予約・ブロック・返金処理は残す。`DIRECT_MESSAGES_DELIVERY_ENABLED=false`はDMおよび新設した精算通知の外部配送を停止するため、運営画面で処理を監視する。公開後の障害対応でmigrationをdownしてDM履歴を消さない。

削除後のバックアップ残存上限35日は運用要件。実際の世代構成・保管先・35日以内の消去は未確認で、機能有効化前の条件とする。アプリの鍵と非公開領域を適切に保管し、最新のプライバシー状態を古いDBバックアップとは独立して維持する。

```sh
php artisan direct-messages:recovery export /absolute/private/path/latest-privacy-state.enc
# 復元時はメンテナンスに入り、全ワーカーと定期実行を停止する。
php artisan direct-messages:recovery apply /absolute/private/path/latest-privacy-state.enc
```

exportは削除履歴・方向付きブロック・退会・証拠保存期限を暗号化して出力する。本文・画像は含まない。applyはメンテナンス中のみ実行でき、削除・ブロック・退会状態を復元DBへ適用し、古いDM通知を抑止する。**最新の状態を確保できない場合は公開を再開しない。** このコマンドだけでDB復元後の決済整合は保証しないため、Stripeの実際の支払/返金・予約・台帳・通知配送状況を照合してから再開する。
