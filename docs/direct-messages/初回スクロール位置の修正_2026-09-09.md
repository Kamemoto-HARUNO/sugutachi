# 初回表示のスクロール位置

iPhone版Chromeで、ホームなどを開くと少し下へスクロールした状態になり、手動で先頭へ戻せばロゴが見える報告への対応。

既存の画面遷移処理は初回表示を対象外にしていた。新しいドキュメントを開いたときは先頭へ揃え、読み込み直後の位置復元にも対応するため、load後の次フレームと400ms後に補正する。補正は初回だけの有限処理で、タッチ・ホイール・キー操作・フォーカス移動が始まれば即座に終了する。別URLへの移動やpagehideでも破棄する。

戻る・進むで読み込むドキュメント、ページ内アンカー付きURLは対象外。BFCacheからの復帰時に処理を再実行しない。`history.scrollRestoration` の設定は変更しない。既存のSPA画面遷移時の先頭移動・POP時の位置保持も維持する。

## 検証

- 型チェック・ビルド・差分チェック成功。
- Chromiumのブラウザ内だけで、loadの100ms後に110pxの位置復元を模擬。修正前の開発環境は650ms時点も110px、修正後のローカルは0pxへ補正し、ホームの上余白40pxを確認。
- 同じ模擬処理の前にtouchstartが発生すると、650ms時点でも110pxを保持し、ユーザー操作を上書きしない。
- ホームを500pxスクロール→ヘルプ→戻るで500pxへ復帰。
- ブラウザ実行エラーなし。

これは実機Chrome内部の動作を再現した証明ではなく、報告された位置ずれに対するアプリ側の補正を検証したもの。開発環境反映後、報告元iPhoneのChromeで初回表示を再確認する。本番・予約・決済・通知・DBは変更しない。
