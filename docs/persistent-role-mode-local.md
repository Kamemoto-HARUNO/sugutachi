# モード表示・切り替えの改善（ローカル確認）

2026-09-10。作業ブランチ `fix/persistent-role-mode`。開発・本番環境への反映は未実施。

## 変更内容

- ログイン中は全画面の上部にモードバーを表示し、ドロップダウンから切り替える。
- URLに応じたモードの自動変更を廃止。他の役割の専用画面は内容を表示する前に切り替え案内を出す。
- 選択したモードはアカウントごとに同じブラウザで保持。再読み込み・再ログインで復元する。既存の保存値は現在のログインアカウントへ一度だけ移行する。
- アカウント情報の再取得や他タブの選択で、操作中のタブのモードを勝手に変更しない。
- マイページは選択中のダッシュボードへ直接移動。メッセージ・通知・進行中の予約は選択中の役割に合わせる。
- 共通の一覧 `/therapists` を追加。旧 `/user/therapists` は検索条件を保って転送する。
- 利用者モードの一覧は既存の住所を基準とした検索。キャスト／ゲストの一覧は住所不要の公開閲覧、キャスト名検索、ページ送り、地域ページへの入口を提供する。
- キャストモードのトップ・詳細では利用者の保存住所を取得しない。お気に入り状態・予約状況も表示しない。
- 詳細から予約・質問・お気に入りへ進む際は、役割を明示したボタンで利用者モードへ切り替える。未登録の場合は利用者モード追加へ案内する。
- 閲覧ページ上のモード切り替えではキャスト・メニュー・日時などのURL条件を維持。役割専用ページ上の切り替えは切り替え先のダッシュボード／メッセージ一覧に戻る。
- 自分の公開プロフィールの予約・質問は不可。フッターもプロフィール編集への入口に統一。
- サポートの新規問い合わせは現在のモードを明示して送る。APIで保有する役割か確認する。既存チケットは引き続きアカウント単位。
- DM用の表示領域からモードバーの高さを差し引き、キーボード等による表示領域の変化に追従する。

## 確認結果

- 全383テスト・3,310 assertions成功。追加テストは、キャストだけのアカウントでの住所不要検索・ページ送り・名前検索・ブロック／非公開の保持・サポートの役割指定と拒否を確認。
- 既存のサポート配信テスト1件は実行時刻により日付境界をまたいで期待値が変わるため、テストの時計を固定。配信実装は変更していない。
- 型チェック・ビルド・差分チェック成功。既存の大きなJSバンドルに対する警告あり。
- ブラウザでキャストモードのトップ・一覧・詳細、旧URL転送、再読み込み後の保持、別モードの予約リンクの案内を確認。
- キャストモードのトップで保存住所の取得リクエスト0件、利用者住所の表示なしを確認。
- 予約への切り替え後に同じキャストの利用者向け詳細へ移行。DM一覧・詳細・予約の連絡タブの表示も確認。
- 幅320px／390pxで横にはみ出さないことを確認。DMは高さ844px時に上部44px・本文800px、表示領域を480pxへ縮めても入力欄が画面内に収まる。
- ブラウザエラーなし。実機iPhoneのキーボード・ブラウザバーの操作は利用者確認待ち。
