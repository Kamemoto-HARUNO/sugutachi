# 通知一覧・既読連動の改善

2026-09-10。対象はローカルから開発環境。本番反映は別途。

## 表示と操作

- 選択モード宛てと、明示的な `shared`（アカウント共通）の通知だけを一覧・バッジ・一括既読の対象にする。役割未指定のAPIは共通通知のみ。権限失効済みの役割は指定不可。
- 過去の通知は宛先役割、境界を確認したリンク先、予約の参加者、サポートチケットの依頼者役割、宛先を一意に決められる通知種別の順で復元する。判定できない通知は `unknown` として保持し、共通通知へ流さない。
- DMは会話と受信側の役割、予約メッセージは予約IDと受信側の役割ごとに1カードへ集約。集約後に取得上限を適用する。未読バッジは未読カード数、カード本文は未確認のメッセージ通知数を示す。
- 予約成立・返金等の通知は集約しない。既読履歴は残り、同じ会話の次回受信でカードが更新される。
- 通知カード全体をクリック／Enter／Spaceで操作する。役割ラベルと個別の詳細・既読ボタンを削除。未読は丸印と背景色で表示する。遷移先のないお知らせは本文を省略せず、カード操作で既読にする。
- カードを開くと、そのカードの表示時点までの通知だけを既読にする。メッセージ本文の既読は変えない。一括既読も一覧取得時のIDを上限にする。
- 実際にメッセージを読んだときは、受信アカウント・役割・メッセージIDを限定して対応通知も既読にする。予約チャットも、表示中のタブでメッセージが500ms見えてから自動既読にする。ブロック時の既読制限はサーバーで維持する。
- メッセージ既読時に通知バッジを更新し、通知ページも更新イベント・フォーカス復帰・30秒ごとの確認で同期する。

## 配信・データの扱い

既存の1通ごとの通知レコードは削除・統合せず、一覧APIで集約する。DMのメール・プッシュ配信が参照する通知IDと履歴は維持する。新規メールやプッシュの配信方式は変更しない。

通知テーブルに `audience_role` と `conversation_key`、絞り込み用索引を追加する。新しい通知は作成時に値を設定する。既存通知は次のコマンドで整理する。

```
php artisan migrate --force
php artisan notifications:reconcile-inbox
```

整理処理は通知の宛先・集約キーと、既に読まれたメッセージに対応する通知の既読状態だけを更新する。通知を再送しない。繰り返して実行できる。反映前にDBとアプリ・環境設定をバックアップし、反映・migration・整理完了まで開発環境をメンテナンス表示にする。

ロールバック時も追加カラムは旧コードで無視できるため、原則として旧アプリへ戻す。DB全体の復元は、その後の利用による更新を失わないよう別途判断する。
